🤖 PoC · Demo interactiva · Sistema Multiagente
CAF Copilot — Asistente Agéntico de Adopción Cloud
Demo conceptual (datos hardcodeados) de un sistema multiagente pensado para empresas sin la madurez para tener su información ordenada y a disposición. El objetivo no es solo automatizar un CAF — es establecer una metodología de relevamiento basada en buenas prácticas (con técnicas alternativas cuando un dato no existe) que deje a la organización con todo lo necesario para migrar y, además, sentar las bases para ser IA-Ready.

📋 Fase 0 — Metodología de relevamiento (para empresas sin la info ordenada)
La mayoría de las empresas no tienen estos 16 puntos disponibles ni ordenados — esa es justamente la realidad que este MAS está pensado para abordar. Cada ítem incluye un enlace "¿Sin este dato? Cómo relevarlo" con la técnica de buenas prácticas para obtenerlo (proxy, entrevista, herramienta gratuita, taller) cuando no existe formalmente. El objetivo final no es solo "migrar" — es dejar a la empresa con el ordenamiento de información necesario para ser IA-Ready.
💰 Financiero / Comercial
#1 Facturación actual de licencias VMware/Broadcom (últimas 3 renovaciones)Fuente: Área Compras / Contratos
Si no están ordenadas: pedir directamente al proveedor/reseller un histórico de facturación de los últimos 3 años (lo tienen disponible). Alternativa: revisar los 3 últimos comprobantes de pago en el área de Compras.
#2 Costos de energía, refrigeración y espacio del datacenter (CAPEX/OPEX)Fuente: Facilities / Finanzas
Si no hay prorrateo de costos: usar un estimador estándar (≈ USD 1.500-2.500/año por rack 'ocupado' incluyendo energía+refrigeración+espacio) y validarlo con la factura eléctrica total del edificio dividida por % estimado de consumo del DC.
#3 Headcount y costo del equipo IT que administra infraestructuraFuente: RRHH / CIO
Si no hay costeo formal: relevar en una entrevista de 15 minutos cuántas personas y qué % de su tiempo dedican a tareas de infraestructura (vs. desarrollo/soporte) y multiplicar por su costo full-time.
#4 Presupuesto IT aprobado y ciclo de aprobación de inversionesFuente: CFO
Si no existe un presupuesto formal: preguntar directamente al CFO/CEO cuál fue el último monto aprobado para IT y cómo se aprobó (comité, directorio, informal) — esto define el formato de la propuesta.
🔍 Técnico / Infraestructura
#5 Inventario de VMs: CPU/RAM/storage asignado vs. uso real (P95 30 días)Fuente: Discovery agentless (Matilda / RVTools)
Es el dato más crítico y el que más falta. Si no hay discovery previo: instalar un agente liviano (Matilda, RVTools, o incluso scripts PowerCLI) durante 30 días — no requiere downtime ni cambios. Sin esto, cualquier sizing es una suposición.
#6 Mapa de dependencias entre aplicaciones (qué habla con qué)Fuente: Network traffic analysis
Si nadie lo documentó: usar herramientas de network traffic analysis (NetFlow/sFlow) durante 2 semanas, o como mínimo, taller de 'whiteboard' con los administradores de sistemas dibujando las conexiones conocidas.
#7 Versiones de SO, bases de datos y licenciamiento (BYOL vs. incluido)Fuente: CMDB / inventario manual
Si no hay CMDB: el mismo agente de discovery (Matilda/RVTools) detecta SO y versiones automáticamente. Para licencias, contactar al proveedor de cada software con el listado de servidores para que confirme el tipo de licencia.
#8 Topología de red actual y conectividad entre sedesFuente: Diagramas de red / equipo NetOps
Si no hay diagramas actualizados: pedir al proveedor de conectividad actual (factura/contrato) el detalle de enlaces contratados, y complementar con un 'traceroute' básico entre sedes para validar la topología real.
🏢 Organizacional / Negocio
#9 Criticidad de cada aplicación (Tier 1/2/3) según el negocioFuente: Entrevistas con dueños de proceso
Si nunca se clasificó: taller de 1 hora con los dueños de proceso (no IT) usando una pregunta simple: '¿Qué pasa si este sistema no funciona durante 4 horas? ¿Y durante 24?' — la respuesta clasifica automáticamente el Tier.
#10 Madurez del equipo IT: certificaciones cloud existentes, experiencia previaFuente: Entrevista RRHH/CIO
Si no hay registro: encuesta de 5 minutos al equipo (autoevaluación) + revisar perfiles de LinkedIn del equipo IT como proxy rápido de certificaciones y experiencia previa en cloud.
#11 Estructura de decisión: quién aprueba qué y con qué presupuestoFuente: Entrevista CIO/CFO
Si no está formalizado: preguntar directamente '¿quién firmó la última compra de tecnología de más de USD 10K?' — la respuesta real (no el organigrama teórico) define el verdadero centro de decisión.
#12 Iniciativas de negocio que dependen de IT (expansión, nuevas plantas, IA)Fuente: Entrevista C-level
Si no hay un plan estratégico documentado: entrevista de 20 minutos con un C-level preguntando '¿qué planea la empresa para los próximos 18-24 meses que requiera más capacidad tecnológica?'
🔐 Compliance / Riesgo
#13 Regulaciones aplicables (BCRA, ENACOM, ISO, sector específico)Fuente: Legal / Compliance
Si Legal no tiene un mapeo claro: identificar el sector de la empresa y aplicar la matriz sectorial estándar (banca→BCRA, telco→ENACOM, salud→Ley 25.326+HL7, etc.) como punto de partida, y validar con Legal.
#14 Última auditoría de seguridad y hallazgos abiertosFuente: CISO / Auditoría interna
Si nunca se hizo una auditoría formal: ejecutar un scan básico de vulnerabilidades/configuración (gratuito con herramientas como Lynis, AWS Trusted Advisor en modo free, o Microsoft Secure Score) como línea base.
#15 Política de backup actual y última prueba de DR realizadaFuente: Equipo de Infraestructura
Si 'hacemos backup' pero nunca se probó restaurar: ese es el hallazgo en sí mismo. Proponer una prueba de restauración guiada de 1 sistema no crítico como parte del relevamiento — el resultado (funciona / no funciona / tarda X horas) es el dato.
#16 Restricciones de residencia de datos (qué no puede salir del país)Fuente: Legal / Compliance
Si no hay política escrita: aplicar la regla general por tipo de dato (datos personales de clientes → Ley 25.326, datos financieros regulados → BCRA si aplica, resto → sin restricción) y validar con Legal solo los casos grises.

CAF Copilot — Sesión de análisis
Cliente demo: Industria manufacturera, 600 empleados
🧭
CAF Copilot · Orchestrator
¡Hola! Soy el orquestador del CAF Copilot. Antes de analizar nada, el Data Collection Agent ya relevó la información de la empresa (checklist de la izquierda — financiero, técnico, organizacional y compliance). Con esos 16 datos recopilados, voy a coordinar 5 agentes especializados para armar el análisis completo: madurez, business case, arquitectura, gobernanza/seguridad y roadmap. Tildá los ítems del relevamiento (o usá el botón de simular) y arrancamos.
Industria manufacturera, 600 empleados, datacenter propio con licencias VMware, sin estrategia cloud formal. Buscamos evaluar migración.
Nota sobre este PoC: Esta demo usa contenido 100% hardcodeado para ilustrar el flujo conceptual del sistema multiagente — no hay LLMs ni orquestación real corriendo. Un PoC funcional requeriría: (1) un framework de orquestación tipo LangGraph/CrewAI/AutoGen, (2) una base de conocimiento RAG con la documentación de AWS/Azure/GCP CAF + el material interno de Personal Tech, (3) conectores a datos reales del cliente (CRM, facturación, discovery técnico tipo Matilda), y (4) una librería de "técnicas de relevamiento alternativo" (los hints "¿Sin este dato?") curada con casos reales para que el agente sugiera la mejor alternativa según el sector y madurez del cliente. La trazabilidad (tags #1-16) muestra de dónde sale cada número — clave para que la propuesta sea defendible ante el cliente, no una caja negra. Estimación de esfuerzo: 4–8 semanas para un piloto funcional con un cliente real.
