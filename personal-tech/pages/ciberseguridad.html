01 — El panorama de amenazas (Threat Landscape)
El mapa del adversario — actores, motivaciones y vectores de ataque
▼

El Threat Landscape es el mapa completo de amenazas que enfrenta una organización: quiénes atacan, por qué, cómo y con qué herramientas. Entenderlo es el prerequisito de cualquier estrategia de seguridad. No se puede defender lo que no se conoce.

Vectores de ataque
Por dónde entran los atacantes — los caminos de ataque más frecuentes
Basado en Fortinet Threat Landscape Introduction
▼
📧
Email / Phishing
Vector #1. El atacante envía un correo que simula ser de una entidad confiable. El usuario hace click o ingresa credenciales. El 90% de los incidentes empiezan con un email.
🌐
Web / Drive-by Download
Sitio legítimo comprometido que sirve malware al visitarlo. El usuario no necesita hacer nada — el exploit se ejecuta al cargar la página.
🔌
Dispositivos físicos (USB)
USB con malware dejado en el estacionamiento o sala de espera. La curiosidad humana hace el resto. Vector de APTs para atacar redes air-gapped.
🔓
Vulnerabilidades sin parchear
Software con vulnerabilidades conocidas y sin actualizar. Los atacantes escanean internet continuamente buscando versiones vulnerables. Time-to-exploit promedio: 15 días.
🤝
Supply Chain (Cadena de suministro)
Comprometer a un proveedor de software o servicio para llegar a sus clientes. SolarWinds (2020): atacaron la cadena de suministro para llegar a 18.000 organizaciones.
📶
WiFi no seguro / MitM
Redes WiFi abiertas permiten ataques de "man in the middle". El atacante intercepta el tráfico entre el usuario y el servidor sin que ninguno se entere.

#FaseQué hace el atacanteCómo defenderlo
1ReconocimientoRecopila información: emails, tecnologías usadas, empleados (LinkedIn), IPs públicas, vulnerabilidades conocidas.Reducir superficie pública. Monitorear lo que se expone en internet sobre la organización.

02 — Tipos de ataques y malware
Ransomware · Phishing · DDoS · APT · SQL Injection · Zero-day — el catálogo del adversario
▼
Ataques más frecuentes en empresas
Los 10 ataques que un consultor cloud debe conocer — con impacto empresarial real
▼
Malware
Ransomware
CRÍTICO
Cifra todos los archivos de la organización y exige rescate para recuperarlos. Hoy también roba los datos antes de cifrarlos (doble extorsión). El impacto promedio supera los $4.4M incluyendo downtime.
LockBit, BlackCat, Cl0p — grupos con modelos de negocio RaaS (Ransomware as a Service).
Ingeniería Social
Phishing / Spear Phishing
ALTO
Email que simula ser de una entidad confiable para robar credenciales o ejecutar malware. Spear Phishing: personalizado para una persona específica usando información de LinkedIn/redes.
Email del "CEO" pidiendo transferencia urgente. Notificación falsa de banco con link a sitio idéntico.
Red
DDoS — Denegación de Servicio
ALTO
Inundación masiva de tráfico que colapsa los servidores, dejando el servicio inaccesible para los usuarios legítimos. Cada minuto de caída en ecommerce puede costar miles de dólares.
Ataques de 1 Tbps+ contra bancos argentinos. Amplificación DNS/NTP para multiplicar el volumen.
APT
Advanced Persistent Threat
CRÍTICO
Ataque silencioso de largo plazo por actores sofisticados (estados, grupos organizados). Se instalan en la red y permanecen sin ser detectados durante meses o años, extrayendo información continuamente.
Permanencia promedio antes de detección: 197 días. El atacante "vive" en la red mientras opera normalmente.
Web App
SQL Injection / XSS
ALTO
SQL Injection: inserta comandos SQL en formularios web para extraer o modificar la base de datos. XSS (Cross-Site Scripting): inyecta código malicioso en páginas web que se ejecuta en el navegador del visitante.
Filtración masiva de datos de clientes de una base de datos no sanitizada.
Credenciales
Credential Stuffing / BFA
ALTO
Uso automatizado de listas de credenciales filtradas (compradas en la dark web) para intentar acceder a múltiples servicios. El 65% de los usuarios reutiliza contraseñas entre servicios.
Compran lista de 500M credenciales de un breach anterior y las prueban automáticamente en portales corporativos.
Vulnerabilidad
Zero-Day Exploit
CRÍTICO
Vulnerabilidad desconocida por el fabricante del software — no existe parche disponible. Los actores de Estado y grupos sofisticados pagan millones por estos exploits.
Log4Shell (2021): vulnerabilidad zero-day en una librería Java usada en millones de aplicaciones. Explotada masivamente en 48hs.
Movimiento lateral
Pass the Hash / Kerberoasting
ALTO
Una vez dentro de la red, el atacante se mueve entre sistemas usando credenciales robadas o tickets de autenticación comprometidos en Active Directory para escalar privilegios.
Atacante entra por un PC de empleado → roba ticket Kerberos → accede al servidor de dominio → controla toda la red.

03 — Marcos y arquitecturas de seguridad modernas
SASE · SSE · Zero Trust · Hub-and-Spoke (obsoleto) — el mapa de la evolución
▼

La ciberseguridad moderna no es un producto — es una arquitectura. SASE, SSE y Zero Trust no son tecnologías que se compran, son modelos arquitectónicos que guían cómo se diseña y opera la seguridad. El modelo perimetral antiguo (Hub-and-Spoke) no alcanza para el mundo cloud y trabajo híbrido.

Los 4 marcos en detalle
SASE · SSE · Zero Trust · Modelo Perimetral — definiciones, diferencias y cuándo aplica cada uno
Basado en el documento Cloud Security adjunto
▼
🌐
SASE
Secure Access Service Edge
Convergencia total: red + seguridad
Modelo arquitectónico alojado en la nube que unifica servicios de red (SD-WAN) con funciones de seguridad avanzadas (ZTNA, CASB, SWG, FWaaS) en una sola plataforma nativa. El usuario se conecta al punto de presencia SASE más cercano y desde allí accede de forma segura a cualquier aplicación.
Casos de uso: Empresas con alta dispersión geográfica, sucursales físicas y personal remoto que requieren acceso ágil y seguro a aplicaciones cloud, eliminando la latencia del tráfico centralizado hacia un datacenter.
🔒
SSE
Security Service Edge
SASE sin la parte de red
Subconjunto directo de SASE que agrupa exclusivamente las capacidades de seguridad (ZTNA, CASB, SWG, FWaaS), omitiendo la gestión de la red física (SD-WAN). Ideal cuando la red ya está gestionada.
Casos de uso: Organizaciones que ya cuentan con infraestructura de conectividad estable (MPLS, SD-WAN propia) y solo necesitan desplegar una capa de protección cloud sobre lo que ya tienen.
🚫
Zero Trust Architecture (ZTA)
Filosofía de identidad y contexto
"Nunca confiar. Siempre verificar."
Marco estratégico guiado por la premisa de "nunca confiar, siempre verificar". Ningún usuario o dispositivo es seguro por defecto, ni siquiera dentro del perímetro. Exige autenticación continua y el principio de mínimo privilegio.
Casos de uso: Base fundamental para mitigar movimientos laterales de atacantes y proteger entornos de trabajo híbridos frente a credenciales comprometidas. No es un producto — es una filosofía que impregna toda la arquitectura.
🏚
Modelo Perimetral (Hub-and-Spoke)
⚠️ OBSOLETO
Seguridad basada en ubicación física
Metodología heredada que asume que todo lo que está "dentro" de la red es confiable. Centraliza el tráfico de sucursales mediante MPLS/VPN hacia el datacenter principal para su inspección.
Por qué falla hoy: El 70% de las aplicaciones ya están en SaaS o cloud. El tráfico tiene que salir a internet igual. Centralizar sólo agrega latencia sin agregar seguridad. El modelo asume que el atacante está "afuera" — y ya vimos que no es así.

04 — Zero Trust: la filosofía que reemplazó al perímetro
"Nunca confiar. Siempre verificar." — los 5 pilares y cómo implementarlos
▼

Zero Trust no es un producto que se compra — es una filosofía que redefine cómo se piensa la seguridad. El modelo antiguo asumía que todo lo "interno" era confiable. Zero Trust asume que cualquier usuario, dispositivo o conexión puede estar comprometido — incluso si están dentro de la red corporativa.

Los 5 pilares de Zero Trust
Identidad · Dispositivo · Red · Aplicación · Dato — los 5 planos que ZT protege
▼
👤
Pilar 1: Identidad
Verificar siempre quién está accediendo. MFA obligatorio. Acceso condicional (¿desde qué dispositivo? ¿en qué hora? ¿desde qué lugar?). Las credenciales nunca son suficientes por sí solas.
💻
Pilar 2: Dispositivo
Verificar el estado del dispositivo antes de permitir acceso: ¿está actualizado? ¿tiene antivirus activo? ¿es un dispositivo corporativo o personal? Un celular sin parches no puede acceder a datos críticos.
🌐
Pilar 3: Red
Segmentar la red en microsegmentos. Un atacante que entra por un punto no puede moverse libremente. ZTNA reemplaza la VPN tradicional que daba acceso a toda la red.
🖥
Pilar 4: Aplicación
Las aplicaciones no son accesibles desde internet. Solo los usuarios autorizados con dispositivos verificados pueden acceder a cada aplicación específica (no a toda la red).
🗄
Pilar 5: Dato
Clasificar y proteger el dato en sí mismo. Cifrado en tránsito y en reposo. DLP para evitar que datos sensibles salgan de la organización. El dato protegido es la última línea de defensa.
La analogía del hospital: En el modelo antiguo, si tenías credencial de empleado entrás a todo el hospital. En Zero Trust, el médico de cardiología solo puede entrar a la sala de cardiología. La enfermera solo ve los registros de sus pacientes asignados. El técnico de limpieza solo puede estar en las áreas asignadas en su turno. Mismo edificio, acceso mínimo y necesario para cada rol.

05 — Firewalls: evolución de 3 generaciones
5 tuplas → Stateful → NGFW — de filtrar puertos a inspeccionar aplicaciones y comportamientos
▼

El firewall evolucionó de un simple filtro de puertos (1ª gen) a un sistema de inspección de estado (2ª gen) y finalmente a un motor de análisis de aplicaciones, usuarios y contenido (NGFW, 3ª gen). Entender las 5 tuplas es entender la base de todo lo que vino después.

Las 5 Tuplas — la "matrícula" del paquete
IP origen · IP destino · Puerto origen · Puerto destino · Protocolo — la base de la inspección de red
Basado en el documento Fortinet Getting Started in Cybersecurity
▼

Cada paquete de red lleva 5 campos fundamentales que los firewalls tradicionales usaban para decidir si lo permitían o bloqueaban:

①
IP de origen
¿Quién envía?
192.168.1.10
②
IP de destino
¿A quién va?
203.0.113.5
③
Puerto origen
App emisora
Puerto 54321
④
Puerto destino
Servicio receptor
443 (HTTPS)
⑤
Protocolo
Cómo viaja
TCP / UDP / ICMP
Límite del enfoque de 5 tuplas: Un atacante puede enviar tráfico malicioso desde una IP "permitida" al puerto 443 usando TCP — el firewall de 1ª gen lo deja pasar porque "parece" tráfico HTTPS legítimo. Por eso se necesita inspección más profunda (DPI / NGFW).
Las 3 generaciones
Evolución histórica y capacidades — de filtro de paquetes a NGFW
Basado en el documento Fortinet Getting Started in Cybersecurity
▼
1ª Generación
(1988 – ~1995)
Packet Filter
  • Solo analiza las 5 tuplas
  • Sin estado — cada paquete evaluado individualmente
  • No entiende si es parte de una sesión legítima
  • Fácil de evadir con IP spoofing
2ª Generación
(~1995 – ~2009)
Stateful Inspection
  • Mantiene tabla de conexiones activas
  • Sabe si el paquete es parte de una sesión establecida
  • Bloquea paquetes fuera de contexto
  • Aún no entiende qué aplicación es
3ª Generación — NGFW
(~2009 – presente)
Next-Generation Firewall
  • Deep Packet Inspection (DPI)
  • Identifica la aplicación (Layer 7)
  • Identifica al usuario (integra con AD)
  • IPS integrado (prevención de intrusiones)
  • Inspección SSL/TLS descifrado
  • Sandboxing de archivos sospechosos
CapacidadFirewall tradicionalNGFW
Filtro por IP/puerto✓✓
Inspección de estado (sesión)✓✓
Identificación de aplicación (L7)✗✓ — sabe si es Netflix, Zoom o BitTorrent
Identidad del usuario✗✓ — integra con Active Directory
IPS (Intrusion Prevention)✗✓ — bloquea exploits conocidos en tiempo real
Inspección de tráfico cifrado SSL/TLS✗✓ — descifra, inspecciona y vuelve a cifrar

07 — Seguridad en la nube
Responsabilidad compartida · Virtualización segura · IAM cloud · Postura de seguridad (CSPM)

Seguridad en virtualización
Hypervisor · VM isolation · Snapshots · OVF — la base de la seguridad en infraestructura virtual
Basado en el documento Cloud Security — Virtualización
▼
🔒
Aislamiento de VMs (VM Isolation)
Cada VM opera de forma aislada. Los problemas (incluidos los de seguridad) en una VM no afectan a las otras. El hypervisor es el árbitro que garantiza ese aislamiento — si el hypervisor se compromete, todas las VMs quedan expuestas (VM escape).
📸
Snapshots como respaldo de seguridad
Una snapshot es una foto del estado completo de la VM en un momento. Si hay un incidente (ransomware, corrupción), se puede revertir a la snapshot anterior. Son la primera línea de recuperación ante ransomware en entornos virtualizados.
📦
Dispositivos virtuales (OVF/OVA)
Imágenes preconfiguradas de appliances de seguridad (firewalls, IDS, WAF) que se despliegan en segundos. Los FortiGate-VM, Check Point CloudGuard y Palo Alto VM-Series se despliegan como OVF en VMware o KVM.
🛡
Segmentación de red virtual
Las VLANs y los VNets/VPCs segmentan el tráfico entre VMs aunque estén en el mismo host físico. Un atacante que compromete una VM de desarrollo no puede acceder a las VMs de producción si la red virtual está correctamente segmentada.

09 — Ciberseguridad en Personal Tech
El portfolio de seguridad de Personal Tech y los argumentos de venta
▼

Personal Tech (Telecom Argentina) ofrece ciberseguridad como una capa que se integra sobre su infraestructura de red y cloud. La ventaja competitiva: la seguridad no es un producto externo que se agrega — es parte del tejido de la red.

Portfolio y argumentos
Servicios de seguridad de Personal Tech y cómo posicionarlos frente al cliente
▼
ServicioQué incluyeArgumento de venta
SOC gestionado 24/7Centro de Operaciones de Seguridad con monitoreo continuo, análisis de incidentes y respuesta. Analistas en Argentina que entienden el contexto regulatorio local (BCRA, CNV)."Un SOC propio cuesta $1M+/año en salarios. Personal Tech da el mismo servicio por una fracción del costo, con SLA de respuesta y analistas locales."
DDoS MitigationProtección ante ataques de denegación de servicio en la capa de red, antes de que lleguen al cliente. Scrubbing centers que filtran el tráfico malicioso."El ataque DDoS se absorbe en la red de Telecom — el cliente nunca lo ve. No se puede hacer eso con un appliance on-premise."
Firewall gestionado (FWaaS)FortiGate o Fortinet gestionado por Personal Tech. El cliente tiene el NGFW sin el costo y la complejidad de operarlo."El cliente tiene seguridad de primer nivel sin necesitar un equipo de seguridad propio."
SD-WAN + Seguridad convergidaLa solución SD-WAN de Personal Tech incluye funciones de seguridad (IPS, URL filtering, app control) en la misma plataforma de conectividad."Un solo contrato da conectividad y seguridad. Menos vendors, menos complejidad, un SLA end-to-end."
Ciberseguridad industrial (OT)Seguridad para redes de tecnología operacional: plantas de manufactura, minería, energía. Incluye segmentación IT/OT y monitoreo de protocolos industriales (Modbus, OPC-UA)."La mayoría de los proveedores de ciberseguridad no conocen el mundo OT. Personal Tech tiene experiencia real en Vaca Muerta y minería."
Argumento maestro para la venta de seguridad
"El 95% de los incidentes de seguridad pueden prevenirse con tres controles básicos: MFA en todas las cuentas, parches al día y backups offline. Pero cuando un cliente ya tiene esos tres, el siguiente nivel requiere visibilidad continua, detección de anomalías y respuesta en minutos — no en días. Para eso está el SOC de Personal Tech."

10 — Diccionario de Ciberseguridad A–Z
60+ términos definidos — el glosario completo para cualquier conversación técnica o ejecutiva
▼
A – C
APT · Autenticación · Backdoor · Botnet · Breach · CASB · Cifrado · C2 · CVE
▼
A
APT
Advanced Persistent Threat
Ataque sofisticado y prolongado por actores altamente capacitados (estados, grupos organizados). Se instalan silenciosamente en la red y permanecen meses o años extrayendo información.
APT28 (Fancy Bear, Rusia) — responsable de hackeos a partidos políticos europeos y OTAN.
B
Backdoor
Backdoor / Puerta trasera
Acceso secreto instalado por un atacante (o a veces por el fabricante) que permite entrar al sistema evitando la autenticación normal. Pueden persistir años sin ser detectados.
RAT (Remote Access Trojan) instalado tras un phishing exitoso que da al atacante control total del sistema.
B
Botnet
Botnet
Red de dispositivos infectados controlados remotamente por un atacante (C2). Se usan para DDoS, spam, minería de criptomonedas o como plataforma de lanzamiento de ataques.
Mirai (2016): botnet de 300.000 cámaras IP infectadas que generó el mayor DDoS de la historia hasta ese momento.
C
CASB
Cloud Access Security Broker
Punto de control de seguridad entre los usuarios y los servicios cloud (SaaS, PaaS, IaaS). Supervisa la actividad, aplica políticas y protege datos confidenciales contra fugas.
El CASB detecta que un empleado sube un archivo confidencial a su Google Drive personal y lo bloquea según la política DLP.
C
CVE
Common Vulnerabilities and Exposures
Sistema de identificación estandarizado para vulnerabilidades de seguridad conocidas. Cada CVE tiene un número único (CVE-2024-XXXX) y una puntuación de criticidad (CVSS 0–10).
CVE-2021-44228 (Log4Shell) — CVSS 10.0 (máximo). La vulnerabilidad de Java de 2021 que afectó millones de sistemas.
C
C2 / C&C
Command and Control
Infraestructura que el atacante usa para comunicarse con el malware instalado en los sistemas de la víctima y enviar instrucciones.
El malware instalado en una PC hace consultas DNS aparentemente normales que en realidad son instrucciones codificadas del servidor C2 del atacante.
D – I
DDoS · DLP · EDR · Exploit · Firewall · Hardening · IAM · IDS · IPS
▼
D
DDoS
Distributed Denial of Service
Ataque que inunda de tráfico un servidor o servicio desde miles de fuentes simultáneas, haciendo que sea inaccesible para usuarios legítimos.
Ataque de 3.47 Tbps en 2021 contra un cliente de Microsoft Azure — el mayor registrado hasta ese momento.
D
DLP
Data Loss Prevention
Herramientas y políticas que detectan y previenen el envío de información confidencial fuera de la organización, ya sea por email, USB, nube o cualquier otro canal.
DLP detecta que un empleado intenta enviar por email un archivo Excel con números de tarjetas de crédito y lo bloquea automáticamente.
E
EDR
Endpoint Detection & Response
Solución que monitorea el comportamiento en dispositivos finales (PCs, servidores, móviles) para detectar y responder a amenazas que evadieron las defensas perimetrales.
CrowdStrike Falcon detecta que un proceso inusual intenta cifrar archivos y lo mata automáticamente antes de que el ransomware se propague.
E
Exploit
Exploit
Código o técnica que aprovecha una vulnerabilidad específica de software o hardware para tomar control de un sistema o ejecutar acciones no autorizadas.
EternalBlue: exploit desarrollado por la NSA que aprovechaba una vulnerabilidad en SMB de Windows. Filtrado y usado en WannaCry/NotPetya.
H
Hardening
Hardening / Bastionado
Proceso de reducir la superficie de ataque de un sistema: desactivar servicios innecesarios, cambiar configuraciones por defecto, aplicar mínimo privilegio, cerrar puertos no usados, eliminar software innecesario.
Bastionar un servidor web: desactivar FTP, cambiar el banner de servidor, deshabilitar métodos HTTP innecesarios (PUT, DELETE), instalar solo los módulos necesarios.
I
IAM
Identity & Access Management
Marco de políticas y tecnologías que garantiza que los usuarios autorizados tengan el acceso adecuado a los recursos tecnológicos en el momento correcto y nada más.
AWS IAM: el desarrollador tiene acceso solo a los buckets S3 de desarrollo, no a los de producción ni a los de otro equipo.
M – Z
Malware · MFA · NGFW · Phishing · Ransomware · SASE · SIEM · SOC · SSL/TLS · WAF · Zero Trust · ZTNA
▼
M
Malware
Malicious Software
Término paraguas para cualquier software diseñado para dañar, robar, interrumpir o acceder sin autorización. Incluye virus, gusanos, troyanos, ransomware, spyware, adware y rootkits.
Un virus se autorreplica y contagia otros archivos. Un troyano se disfraza de software legítimo. Un rootkit se oculta del sistema operativo.
M
MFA
Multi-Factor Authentication
Verificación de identidad que requiere dos o más factores: algo que sabés (contraseña), algo que tenés (teléfono, token físico), algo que sos (biometría). Bloquea el 99.9% de los ataques de credenciales comprometidas.
Microsoft Authenticator + contraseña. YubiKey físico para cuentas críticas.
N
NGFW
Next-Generation Firewall
Firewall de 3ª generación con inspección profunda de paquetes (DPI), identificación de aplicaciones y usuarios (Layer 7), IPS integrado e inspección SSL.
FortiGate, Palo Alto Networks, Check Point, Cisco FTD. Saben que el tráfico del puerto 443 es Netflix y no HTTPS corporativo.
R
Ransomware
Ransomware
Malware que cifra los archivos de la víctima y exige rescate. Los grupos modernos también roban los datos antes de cifrar (doble extorsión) y amenazan con publicarlos.
LockBit 3.0 — el grupo más activo de 2023. Atacó al BCRA, hospitales y organismos gubernamentales globalmente.
S
SASE
Secure Access Service Edge
Modelo arquitectónico cloud que unifica SD-WAN + ZTNA + CASB + SWG + FWaaS en una sola plataforma. Propuesto por Gartner en 2019 como el futuro de la seguridad de red.
Fortinet SASE, Zscaler, Palo Alto Prisma Access, Cisco Umbrella.
S
SOC
Security Operations Center
Equipo dedicado y sala de operaciones que monitorea la seguridad 24/7, detecta incidentes, investiga y coordina la respuesta. Usa SIEM, XDR y playbooks de respuesta automatizada.
Un SOC propio cuesta +$1M/año. Personal Tech ofrece SOC gestionado como servicio (SOC-as-a-Service).
W
WAF
Web Application Firewall
Firewall especializado para aplicaciones web. Bloquea ataques de capa 7: SQL Injection, XSS, CSRF, inclusión de archivos, etc. Se ubica delante del servidor web.
AWS WAF, Azure WAF, F5, ModSecurity. Si la app tiene vulnerabilidades no parcheadas, el WAF puede mitigar el riesgo mientras se corrige el código.
Z
Zero Trust
Zero Trust Architecture (ZTA)
Filosofía de seguridad que elimina la confianza implícita: ningún usuario, dispositivo o sistema es confiable por defecto. Todo requiere verificación continua de identidad, dispositivo y contexto.
NIST SP 800-207 es el estándar de referencia para implementar ZTA. El modelo de Biden (EO 14028) lo declaró obligatorio para agencias federales de EE.UU.
Z
ZTNA
Zero Trust Network Access
Tecnología que crea límites de acceso seguros alrededor de aplicaciones específicas basados en identidad del usuario y postura del dispositivo. Reemplaza a la VPN tradicional.
Fortinet ZTNA, Zscaler Private Access, Cloudflare Access. El usuario accede solo a la app que necesita — no a toda la red corporativa.
