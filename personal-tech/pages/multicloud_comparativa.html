01 — Infraestructura (IaaS) · Cómputo
▼

La base de toda estrategia cloud. Los servicios IaaS proveen servidores virtuales (VMs), capacidad de cómputo bajo demanda y opciones de hardware especializado (GPUs, FPGAs). AWS domina en variedad de instancias; Azure en integración con entornos Microsoft; GCP en precios por cómputo puro; Oracle Cloud en instancias bare metal económicas.

Servidores
Máquinas Virtuales (VMs)
Servidores en la nube de propósito general con pago por hora
▼
Qué es: una computadora completa que corre sobre el hardware del proveedor cloud. Vos elegís cuántas CPUs, cuánta RAM y qué sistema operativo. Podés tenerla lista en minutos y pagarla por hora.
Característica 🟠 AWS 🔵 Azure 🔷 GCP 🟦 IBM 🔴 Oracle 🟥 Huawei
Servicio EC2Elastic Compute Cloud Azure Virtual Machines Compute Engine IBM VPC Virtual Servers OCI ComputeBare Metal + VM ECSElastic Cloud Server
Variedad 500+ tipos de instancia. Máxima variedad del mercado. Alta variedad. Familias D, E, F, N (GPU), H (HPC). Instancias personalizadas (vCPU/RAM a medida). Diferenciador clave. Menor variedad pero integración con mainframe Z. Bare metal disponible al precio de VM. Ventaja de costo. Variedad media, muy competitivo en Asia y LATAM.
Modelo de precio On-demand · Reserved (hasta -72%) · Spot (hasta -90%, interrumpible) Pay-as-you-go · Reserved · Spot (Eviction) On-demand · Committed use · Preemptible · Spot Pay-as-you-go · Reservado On-demand · Universal Credits Pay-per-use · Anuales prepago
Diferenciador Mayor ecosistema. Graviton (ARM propio, -40% costo vs x86). Integración nativa con Windows Server, AD y SQL Server sin licencia extra. Custom machine types: pagás exactamente lo que necesitás. Hybrid Cloud con IBM Z (mainframe). Único en el mercado. Bare metal al mismo precio que VMs. Ideal para Oracle DB. Mejor precio en algunos mercados, fuerte en Latinoamérica B2B.
¿Cuándo mencionar cada uno en una venta? AWS si el cliente ya tiene workloads AWS o quiere máxima variedad. Azure si el cliente es Microsoft-first (Windows, SQL Server, AD). GCP si quiere optimizar costo de cómputo exacto. Oracle si corre Oracle DB y quiere reducir costos de licencia. IBM si tiene sistemas legados mainframe.
VPS Simple
VPS para desarrolladores y pequeñas cargas
Precio fijo mensual, configuración simplificada — equivalente al SVP de Personal Tech
▼
Qué es: versión simplificada de los servidores virtuales, con precio fijo mensual (no por hora), plantillas preconfiguradas y panel de gestión simple. Ideal para desarrolladores, sitios web, WordPress, apps pequeñas. La misma propuesta que el SVP de Personal Tech, pero en el ecosistema del hyperscaler.

Serverless
Funciones serverless (FaaS)

02 — Almacenamiento
▼

Almacenamiento de objetos, bloques y archivos. S3 de AWS es el estándar de facto del mercado y la API que todos replican. Para clientes de Personal Tech el argumento clave es que el dato permanece en Argentina, a diferencia de todos los hyperscalers que lo guardan en el exterior.

Objetos
Object Storage (tipo S3)
Almacenamiento ilimitado de archivos, backups, datos no estructurados, imágenes, videos
▼
Qué es: como un disco duro infinito en internet donde guardás cualquier archivo (un backup de 500GB, millones de imágenes, logs, videos) y accedés por una URL o API. No tiene límite de tamaño total y pagás por lo que usás.
Aspecto 🟠 AWS S3 🔵 Azure Blob Storage 🔷 Cloud Storage 🟦 IBM Cloud Object Storage 🔴 OCI Object Storage
Nombre Simple Storage Service (S3) Azure Blob Storage Cloud Storage IBM COS OCI Object Storage
Durabilidad 99,999999999% (11 nueves) 99,999999999% (LRS/GRS) 99,999999999% (multi-región) 99,999999999% geo-disperso 99,999999999%
Clases/tiers Standard · Infrequent Access · Glacier (archivo, muy barato) · Deep Archive Hot · Cool · Cold · Archive Standard · Nearline · Coldline · Archive Standard · Vault · Cold Vault · Flex Standard · Infrequent Access · Archive
Egress fees Sí — cobra por datos que salen de AWS. Argumento de venta contra AWS. Sí — cobra por salida de datos de Azure. Sí (pero el primero 1TB/mes gratis hacia internet) Sí, similar al resto. Sin egress fees entre regiones OCI. Diferenciador fuerte.
Diferenciador Ecosistema más maduro. API S3 es el estándar que todos replican. Glacier es el más económico para archivo de largo plazo. Mejor integración con Azure Data Lake y análisis de big data. Mejor consistencia global multi-región. Mejor para apps globales. Almacenamiento geoespacialmente disperso, ideal para compliance estricto. Sin egress fees + gratuito hasta 10GB/mes en Free Tier.
Argumento Personal Tech: Personal Tech ofrece Object Storage equivalente (compatible con API S3) pero el dato queda en Argentina. Sin egress fees en pesos. Para empresas con dato regulado o confidencial, esto es el argumento definitivo frente a cualquier hyperscaler.
Bloques

Disco duro virtual para montar en servidores — bases de datos, sistemas operativos
▼
Qué es: el disco duro de la VM. Si Object Storage es como una caja de archivos, Block Storage es el disco rígido que montás dentro del servidor. Necesitás uno para instalar el sistema operativo y correr bases de datos.

03 — Bases de Datos (DBaaS)
▼

Base de datos como servicio gestionado: el proveedor se encarga de los backups, parchado, failover y alta disponibilidad. AWS tiene el catálogo más amplio; Azure es la opción obvia para entornos SQL Server; Oracle es imbatible para Oracle Database; GCP lidera en bases de datos globalmente distribuidas.

SQL Relacional
Bases de datos relacionales gestionadas (PostgreSQL, MySQL, SQL Server)
Motor SQL tradicional sin gestionar el servidor de base de datos
▼
Proveedor 🟠 AWS 🔵 Azure 🔷 GCP 🟦 IBM 🔴 Oracle
Servicio RDS Amazon RDS — soporta MySQL, PostgreSQL, MariaDB, SQL Server, Oracle. Más Amazon Aurora (motor propio 5x más rápido). Azure SQL Database — best in class para SQL Server. Azure DB for PostgreSQL / MySQL también disponibles. Cloud SQL — MySQL, PostgreSQL, SQL Server. Y AlloyDB (PostgreSQL compatible, alta performance). IBM Db2 on Cloud — fuerte en entornos enterprise con legado IBM. Oracle Autonomous Database — auto-parchado, auto-tuning, sin DBA. Ideal para Oracle ERP/EBS.
Aurora Motor propio de AWS compatible con MySQL/PostgreSQL. 5x más rápido que MySQL estándar. Multi-master disponible. Serverless option. No tiene equivalente propio — Hyperscale SQL Server es lo más cercano. AlloyDB for PostgreSQL es la respuesta de GCP: 4x más rápido que PostgreSQL estándar. No tiene equivalente directo. Autonomous DB es el equivalente Oracle — auto-todo, pero solo para Oracle.
Para SQL Server RDS for SQL Server disponible pero sin beneficios de licencia Azure Hybrid. Mejor opción del mercado. Azure Hybrid Benefit: usás las licencias SQL Server que ya tenés, ahorrás hasta 55%. Cloud SQL for SQL Server disponible pero no es el punto fuerte de GCP. No recomendado para SQL Server. No recomendado para SQL Server.

SLA 99,999% de disponibilidad. Distribución global nativa. Firestore + Cloud Bigtable — Firestore para documentos (Firebase), Bigtable para series temporales y analytics.
Columnar DocumentDB (compatible MongoDB) · Keyspaces (Cassandra compatible) Cosmos DB Apache Cassandra API Bigtable — procesamiento de petabytes con latencia milisegundo

Globalmente distribuida
Bases de datos globalmente distribuidas y NewSQL
Para apps con usuarios en todo el mundo que necesitan consistencia y latencia baja en cualquier región
▼

Servicio Amazon Aurora Global / DynamoDB Global Tables Azure Cosmos DB — líder en esta categoría. Multi-región activo-activo nativo. Cloud Spanner — base de datos SQL global, ACID a escala planetaria. Única en el mercado en combinar SQL + distribución global.
Caso de uso Multi-región con failover automático. Apps globales que necesitan leer y escribir desde cualquier región con consistencia configurable. El mejor para apps financieras globales, inventario en tiempo real, reservas de vuelos. SQL semántico + consistencia global sin compromisos.

04 — Redes, CDN y Conectividad Privada
▼

Redes virtuales, balanceo de carga, distribución de contenido y conexiones privadas dedicadas a los hyperscalers. Este vertical es donde Personal Tech tiene su mayor ventaja competitiva: es el partner de conectividad que conecta al cliente con AWS (Direct Connect) y Azure (ExpressRoute) desde Argentina.

Red virtual
VPC — Virtual Private Cloud / Redes virtuales
Tu red privada dentro de la nube — subredes, firewalls, tablas de enrutamiento
▼
Aspecto 🟠 AWS VPC 🔵 Azure VNet 🔷 GCP VPC
Nombre Virtual Private Cloud (VPC) Virtual Network (VNet) Virtual Private Cloud (VPC)
Diferenciador VPC regional. Security Groups por instancia. Transit Gateway para conectar múltiples VPCs. VNet + NSG (Network Security Groups). Mejor integración con Azure AD y entornos híbridos on-premise. VPC global — una sola red que abarca todas las regiones sin VPC peering. Diferenciador único frente a AWS y Azure.
Conexión privada
Conexión privada dedicada a la nube (Direct Connect / ExpressRoute)
Circuito privado desde la empresa al hyperscaler — sin pasar por internet
▼
Qué es: en vez de conectarse a AWS/Azure por internet (con sus variabilidades y riesgos de seguridad), la empresa tiene un circuito privado dedicado que va directamente de su datacenter o sede a los servidores del hyperscaler. Personal Tech provee este circuito como partner certificado.
Aspecto 🟠 AWS Direct Connect 🔵 Azure ExpressRoute 🔷 GCP Cloud Interconnect
Nombre AWS Direct Connect Azure ExpressRoute Cloud Interconnect (Dedicated / Partner)
Cómo se accede desde AR A través de un partner como Personal Tech que tiene conexión directa a los PoPs de AWS. A través de un ExpressRoute Partner. Personal Tech es partner certificado de Azure ExpressRoute. A través de un Partner Interconnect. Menor número de partners en Argentina.
Beneficios Latencia predecible, SLA de red, no pasa por internet, menor costo de egress que por internet. Idem, más integración con Azure AD, Office 365 y servicios Microsoft. Menor costo de egress. SLA 99,9% o 99,99% según tipo.
Arg. de venta Personal Tech Personal Tech puede dar acceso a AWS Direct Connect, Azure ExpressRoute y GCP Cloud Interconnect desde una sola contratación, combinado con cloud propio en el DC de Pacheco. Un solo proveedor para todo. Nadie más puede ofrecer eso en Argentina.
CDN
CDN — Content Delivery Network
Distribuye contenido estático (imágenes, videos, JS) desde servidores cercanos al usuario final
▼
Aspecto 🟠 AWS CloudFront 🔵 Azure CDN / Front Door 🔷 Cloud CDN
PoPs globales 450+ PoPs en 90+ ciudades 130+ PoPs. Azure Front Door agrega WAF y balanceo global. Integrado con la red global de Google. 100+ edge locations.
Diferenciador Mejor integración con S3 y Lambda@Edge (ejecuta código en el edge). Azure Front Door combina CDN + WAF + load balancing global en uno. Integración nativa con Cloud Storage y GKE. Menor latencia dentro de la red Google.

06 — DevOps, Desarrollo & PaaS
▼

Herramientas para que los equipos de desarrollo construyan, prueben y desplieguen aplicaciones más rápido. Incluye CI/CD, plataformas de aplicación gestionadas (PaaS) y herramientas de infraestructura como código. Azure DevOps lidera en entornos enterprise Microsoft; AWS CodePipeline en ecosistema AWS; GCP Cloud Build destaca por velocidad; GitHub Actions es el estándar de facto de la industria.

CI/CD
Pipelines CI/CD — Integración y Entrega Continua
Automatizar build, test y deploy de código en cada commit
▼
Herramienta 🟠 AWS 🔵 Azure 🔷 GCP
CI/CD nativo CodePipeline + CodeBuild + CodeDeploy. Tres servicios separados que se encadenan. Azure DevOps — pipeline completo en un solo producto (Repos, Boards, Pipelines, Artifacts, Test Plans). El más completo para enterprise. Cloud Build — muy rápido, integrado con Artifact Registry y Cloud Deploy.
GitHub Actions GitHub (propiedad de Microsoft/Azure) es el estándar de facto. Azure tiene integración nativa privilegiada. Los tres providers tienen actions runners disponibles.
Infraestructura como código CloudFormation (nativo AWS) · CDK (código Python/JS/TS → CF) · Terraform (multi-cloud, el más usado) Bicep / ARM Templates (nativo Azure) · Terraform Deployment Manager (nativo GCP) · Terraform
PaaS
PaaS — Plataforma de Aplicación Gestionada
Subís el código, el proveedor gestiona el servidor, el OS, el escalado y la disponibilidad
▼
Aspecto 🟠 AWS Elastic Beanstalk 🔵 Azure App Service 🔷 Google App Engine

Soporte nativo para .NET, Node, Python, PHP, Java. SSL, custom domains, deployment slots para blue/green sin costo extra. Autoescalado total, incluyendo escalar a cero. Muy económico para tráfico variable. Dos modos: Standard (más barato) y Flexible.
Mejor para Equipos que quieren PaaS dentro del ecosistema AWS sin aprender Kubernetes. Empresas con stack .NET o PHP. El más fácil para devs Windows. Apps con tráfico muy variable o intermitente — paga solo cuando hay requests.

Kubernetes gestionado
Kubernetes Gestionado (K8s as a Service)
Orquestación de contenedores sin gestionar el control plane de Kubernetes
▼
Aspecto 🟠 Amazon EKS 🔵 Azure AKS 🔷 Google GKE 🟦 IBM ROKS
Qué es Elastic Kubernetes Service. El control plane es gestionado por AWS. Workers son EC2 o Fargate. Azure Kubernetes Service. Control plane gratuito (solo pagás los nodos workers). Integración nativa con Azure AD y Azure DevOps. Google Kubernetes Engine. El inventó Kubernetes. Autopilot mode: GCP gestiona incluso los nodos workers. Red Hat OpenShift on IBM Cloud — Kubernetes con capa enterprise OpenShift encima. El más corporativo.
Precio control plane ~$144/mes por cluster (costo de EKS) Gratuito — solo pagás los VMs workers $73/mes por cluster (Autopilot: sin costo fijo) Incluido en el costo del servicio
Diferenciador Mejor integración con ECR (registry), ALB Ingress y IAM roles por pod. Control plane gratuito + Workload Identity con Azure AD. Mejor para equipos DevOps con Azure. GKE Autopilot: GCP gestiona todo incluyendo los nodos. El más serverless de los tres. Parchado automático sin interrupciones. OpenShift agrega operadores, security policies enterprise y soporte RHEL.

08 — Analítica, Big Data & Ciencia de Datos
▼

Servicios para procesar, analizar y visualizar grandes volúmenes de datos. Incluye data warehouses, streaming en tiempo real, ETL y herramientas de Business Intelligence. AWS Redshift lidera en data warehouse coste-eficiente; GCP BigQuery es el más potente en análisis ad-hoc sin infraestructura; Azure Synapse integra SQL + Spark + Power BI en un solo servicio; IBM lidera en gobernanza de datos enterprise.

Data Warehouse
Data Warehouse en la nube
Analizar petabytes de datos históricos con SQL — sin gestionar servidores
▼
Aspecto 🟠 AWS Redshift 🔵 Azure Synapse 🔷 BigQuery 🟦 IBM Db2 Warehouse
Modelo Columnar basado en PostgreSQL. Serverless disponible. Muy costo-eficiente para grandes volúmenes. Azure Synapse Analytics — combina SQL dedicado (DWH) + Apache Spark + integración nativa con Power BI y Azure ML. Serverless puro. Pagás por query, no por cluster. Sin aprovisionar infraestructura. Procesa PBs en segundos con SQL estándar. Db2 Warehouse on Cloud — fuerte para workloads de reporting de empresas con legado IBM.
Precio modelo Por nodo (RA3): separa cómputo de storage. Serverless: por RPU (Redshift Processing Unit) por segundo. Pool dedicado (por DWU) o Serverless (por TB procesado). $5/TB procesado en queries. Storage a $0.02/GB. Primeros 10GB/mes de queries gratis. Sin clusters. Por vCPU/mes.
Mejor para Grandes volúmenes con queries recurrentes y predecibles. Mejor precio para alto uso continuo. Si el cliente ya usa Azure y quiere integrar DWH con Power BI, ML y Spark en un solo servicio. 13 — Resumen: ¿Cuándo recomendar cada nube?
▼

Guía rápida de criterios de selección por proveedor. Para usarla en conversaciones de preventa cuando el cliente pregunta "¿y qué nube me recomendás?"

🟠 AWS
Cuándo es la mejor opción
Máxima variedad de servicios, ecosistema más maduro, liderazgo de mercado
▼
  • El cliente ya tiene workloads en AWS y quiere consolidar.
  • Necesita la mayor variedad de servicios posibles (200+ servicios).
  • Proyectos de startup o scale-up con equipo técnico cloud-native.
  • Quiere instancias Graviton (ARM, -40% costo vs x86) para workloads de cómputo intensivo.
  • Usa serverless intensivamente (Lambda + DynamoDB + S3 = stack clásico).
  • IA generativa con acceso a múltiples modelos (Bedrock: Claude, Llama, Titan).
¿Por qué AWS es imbatible en esto?
  • 200+ servicios: AWS inició en 2006 y lleva casi 20 años de ventaja de desarrollo. Azure y GCP tienen ~180 y ~100+ servicios respectivamente. La diferencia no es solo cantidad sino madurez — los servicios de AWS llevan años en producción con millones de empresas como casos de uso reales y documentación exhaustiva.
  • Startups y cloud-native: AWS tiene la comunidad developer más grande del mundo. Cualquier ingeniero en el mercado ya conoce AWS. Azure requiere contexto Microsoft-first y GCP tiene menos masa crítica en la comunidad developer global. El time-to-market de un proyecto nuevo en AWS es el más rápido por el acceso a tutoriales, herramientas y soporte comunitario.
  • Graviton ARM -40% costo: Es el único hyperscaler con chip propio de producción masiva para cómputo general. Azure usa Ampere (ARM de terceros) y GCP tiene TPUs solo para ML. Graviton es hardware propietario de Amazon optimizado para sus workloads — el ahorro del 40% vs x86 es real y está documentado en benchmarks independientes.
  • Lambda serverless: Lambda fue el pionero del mercado (2014). Azure Functions llegó dos años después y Cloud Functions de GCP tiene menos integraciones nativas. El ecosistema Lambda tiene más triggers (S3, DynamoDB, SNS, API Gateway, IoT) y más tiempo de batalla comprobado en producción a escala global.
  • Bedrock multi-modelo: Es el único que entrega en una sola API acceso a modelos de Anthropic (Claude), Meta (Llama), Cohere, Stability AI y Amazon Titan. Azure OpenAI solo da acceso a modelos de OpenAI. GCP Vertex AI solo da acceso a modelos de Google. Si el cliente quiere comparar modelos o no depender de un solo vendor de IA, AWS Bedrock es la única opción.

En AWS o GCP, si usás SQL Server, pagás la licencia completa encima del costo del servidor. 14 — Arquitectura de Red: Load Balancer, DDoS y WAF
▼

Una pregunta frecuente en arquitectura cloud: "Si el Load Balancer está expuesto a internet, ¿no es vulnerable a un ataque DDoS?" La respuesta es que tanto Azure como AWS protegen el Load Balancer con capas de defensa integradas que lo convierten en el primer eslabón de seguridad, no en un punto débil. Entender esto es clave para diseñar arquitecturas seguras y explicarlas a clientes.

Concepto base
¿Por qué el Load Balancer va al frente? ¿No es un riesgo?
El Load Balancer no es una VM común — es un servicio gestionado con protección integrada
▼
La analogía: El Load Balancer es como el portero de un edificio de oficinas. Está en la puerta (expuesto al público) por diseño — su trabajo es recibir a todo el que llega y dirigirlo al lugar correcto. Pero ese portero tiene seguridad privada detrás (DDoS Protection), un detector de metales en la entrada (WAF) y una lista de quién puede pasar y quién no (NSG / Security Groups). No está desprotegido — está el más protegido de todos porque es el punto de entrada.
Por qué el Load Balancer no "revienta" ante un DDoS
  • No es un servidor fijo: El Load Balancer no es una VM que vos administrás con CPU y RAM fijos. Es un servicio distribuido que escala horizontalmente de forma automática. Puede absorber un volumen enorme de tráfico sin "reventarse" como pasaría con una VM normal.
  • Azure DDoS Protection: El Load Balancer de Azure está respaldado por Azure DDoS Protection, que filtra tráfico malicioso antes de que llegue a tus recursos. El tráfico anómalo se absorbe en la red global de Microsoft antes de llegar al Load Balancer.
  • AWS Shield: El Elastic Load Balancer (ELB) de AWS está integrado con AWS Shield Standard (gratuito y automático), que detecta y mitiga ataques DDoS de red y transporte en tiempo real, sin intervención manual.
Arquitectura típica
Capas de defensa en una arquitectura cloud bien diseñada
DDoS → WAF → Load Balancer → Firewall (NSG/SG) → VMs → Base de datos
▼
Capa 🟠 AWS 🔵 Azure Qué hace
1 · Anti-DDoS AWS Shield Standard (gratis) / Shield Advanced (pago) Azure DDoS Protection Basic (gratis) / Standard (pago) Filtra tráfico malicioso masivo antes de que llegue a tu infraestructura. Actúa a nivel de red (L3/L4).
2 · WAF AWS WAF integrado con ALB o CloudFront Azure WAF integrado con Application Gateway o Front Door Inspecciona tráfico HTTP/HTTPS y bloquea ataques de aplicación (SQL injection, XSS, OWASP Top 10). Actúa a nivel L7.
3 · Load Balancer ELB (ALB para HTTP, NLB para TCP/UDP) Azure Load Balancer / Application Gateway Distribuye el tráfico entre múltiples instancias. Es el punto de entrada visible desde internet.
4 · Firewall de red Security Groups (por instancia) + NACLs (por subred) NSG — Network Security Groups (por NIC o subred) Controla qué tráfico puede llegar a las VMs. Solo permite puertos específicos desde el Load Balancer.
5 · VMs / App EC2 en subredes privadas VMs en subredes privadas Las VMs están en subredes privadas — no tienen IP pública directa. Solo reciben tráfico desde el Load Balancer.
6 · Base de datos RDS en subred privada, sin acceso desde internet Azure SQL en subred privada, sin acceso desde internet Solo puede recibir conexiones desde las VMs de la aplicación, no desde internet ni desde el Load Balancer directamente.
Conclusión para la venta: Cuando un cliente pregunta "¿el Load Balancer no queda expuesto?", la respuesta es que está expuesto por diseño — es su función — pero está protegido por al menos 3 capas de seguridad antes de que el tráfico llegue a cualquier servidor. La arquitectura cloud bien diseñada es más segura que un servidor on-premise expuesto directamente.

Dimensión VMware Cloud Foundation (VCF) Nutanix Cloud Platform
Modelo Stack completo integrado: vSphere (cómputo) + vSAN (almacenamiento) + NSX (redes) + vCenter (gestión). Arquitectura tradicional modernizada. Hiperconvergencia nativa: cómputo, almacenamiento y red en un solo nodo. Enfoque en simplicidad operativa y automatización desde el origen.
Integración híbrida Arquitectura consistente entre on-premise y cloud (VMware en AWS, Azure VMware Solution, Google VMware Engine). Énfasis en integración con redes y almacenamiento tradicionales. Integración muy fluida con nube pública, privada e híbrida. Nutanix Clusters corre en AWS y Azure con la misma interfaz que on-premise. Foco en simplicidad y automatización.
Gestión Herramientas de gestión integradas pero con mayor complejidad operativa. Requiere expertise en NSX para redes avanzadas. Más control granular sobre cada componente. Panel único (Prism) que gestiona toda la infraestructura con automatización nativa. Curva de aprendizaje más baja. Menos intervención manual requerida.
Fortaleza Mayor énfasis en integración con redes y almacenamiento tradicionales. Ideal para empresas con hardware legado y equipos con expertise VMware existente. Integración muy fluida en entornos de nube privada, híbrida y pública. Enfoque en simplicidad y automatización. Migración más rápida para empresas sin expertise VMware.
Licenciamiento Licenciamiento por socket de CPU. Tras la adquisición de VMware por Broadcom (2023), los precios aumentaron significativamente. Modelo de suscripción por nodo o por core. Más predecible y en algunos casos más económico post-adquisición Broadcom.
Escenario ideal Empresa con infraestructura VMware existente, equipos con expertise en vSphere/NSX, requisitos complejos de red y almacenamiento. Empresa que quiere simplificar su datacenter, migrar a nube híbrida con mínima fricción operativa, o que está evaluando alternativas post-Broadcom.
Contexto importante — post-Broadcom: La adquisición de VMware por Broadcom en 2023 generó aumentos de licencia del 300-500% para muchos clientes. Esto abrió una ventana real para que Nutanix se posicione como alternativa. En conversaciones con clientes que usan VMware, el tema del costo de licenciamiento post-Broadcom es un pain point concreto que se puede atacar con la propuesta de Nutanix o con migración a cloud pública.
